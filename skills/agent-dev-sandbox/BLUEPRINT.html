Agent Dev Sandbox

Target: a secure, isolated, self-contained development environment on a Debian 13 (trixie) host, in which AI coding agents — Claude Code, OpenAI Codex, OpenCode — can develop and test arbitrary codebases (Python 3.13, Node.js 16+, Bun, browser-driven E2E) under strict egress control. 1. Executive summary

The environment is a two-tier "container-first, VM-when-paranoid" design:

  • Tier 1 — daily driver. One persistent, hardened, rootless Podman container per project. The container runs with zero Linux capabilities, no-new-privileges, user-namespace mapping (keep-id), and cgroup caps. It sits on an internal Podman network that has no default route and no external DNS. Egress exists through exactly one path: a rootless Squid gateway enforcing a single-file domain allowlist. Everything an agent needs — Python 3.13, Node 24, Bun, pnpm, uv, git, ripgrep, SQLite, Chromium, Playwright (Node + Python), agent-browser, and the three agent CLIs — is baked into one reproducible image.
  • Tier 2 — hostile workloads. A KVM micro-VM per engagement, booted from an official Debian 13 cloud image, provisioned by cloud-init, with egress enforced by nftables inside the VM (default-deny; only the host proxy and DNS). Inside the VM runs the same container image via rootless Podman — one source of truth, two boundaries.
  • CI mode — same image, throwaway. A third consumption mode (§12): single-shot ephemeral containers for PR checks and batch jobs, with a per-run isolation self-audit, artifact export, walltime caps, shared package caches, and a reaper for orphans. One image, three modes — interactive workspace, ephemeral CI run, container-in-VM.

Secrets never enter images: per-workspace env files (mode 0600) are injected at container start. The verification suite (scripts/50-verify.sh) proves both function and isolation — including negative tests that must fail (direct egress, external DNS) — and its output is the evidence standard for "done".

2. Goals, non-goals, threat model

Goals 1. Develop/test any codebase (representative workload: nordeim/budget-wiser — Next.js 16, React 19, TypeScript strict, Prisma 6 + SQLite, Vitest, Playwright E2E, Bun ≥ 1.3 / Node ≥ 24). 2. Contain the blast radius of agent-executed code: no host filesystem access beyond the project dir, no capabilities, capped resources, no arbitrary network egress. 3. Self-contained: no dependency on host-installed dev tooling; workspaces are disposable and reproducible. 4. Agent-usable: CLIs, browsers, and shell ergonomics work out of the box; a single scripted lifecycle for everything. 5. Auditable: one file is the egress policy; every guarantee has a check.

Non-goals (see references/hardening.md §6) Multi-tenant fleets; TLS interception of proxied traffic; defending against kernel zero-days from Tier-1 workloads (that is Tier 2's job); hiding allowed-channel data flows (e.g., git push to an allowed host).

Threat model — two tiers

Tier 1 (container) Tier 2 (micro-VM)
Use when Building/fixing known codebases (your own, curated OSS) Auditing/running unknown repos, untrusted builds, anything that executes arbitrary scripts
Boundary Kernel namespaces + seccomp + cap-drop (shared kernel) Full hardware-virtualized kernel boundary
Egress Internal network → allowlist proxy (structural: no route exists otherwise) VM nftables default-deny → host allowlist proxy
Residual risk Kernel exploit escapes to host user (mitigated: rootless, non-root, no caps) VM escape (hypervisor-class, rare); supply chain of allowlisted domains
Cost ~2 GB RAM/workspace, seconds to start ~6 GB RAM/VM, one-time 15-30 min golden build, ~30 s per overlay boot

4. Architecture decisions (ADR summary)

D1 — Podman (rootless) over Docker CE. Rootless Podman maps the container's root to an unprivileged host user — a container-root escape lands on a permissionless uid, not host root. No setuid daemon; lifecycle via systemd user units (Quadlet). Docker's daemon requires root or rootlesskit wrappers and adds a docker.sock foot-gun this design refuses to have. Podman 5.4 in trixie supports everything needed (defined networks, --internal, keep-id:uid=, Quadlet, multi-Network=).

D2 — Egress enforcement by network topology, not by env-var etiquette. podman network create --internal (verified against podman-network-create(1)) gives attached containers no default route, disables IP forwarding on the bridge, and makes aardvark-dns answer only container names (everything else NXDOMAIN). Workspaces cannot bypass the proxy even if they ignore proxy env vars — there is no route to bypass with. The gateway is dual-homed: agent-egress (normal NAT network) + agent-internal (the isolated side). An env-var-only proxy would be trivially bypassable; host-firewall approaches cannot distinguish rootless container traffic from the user's own processes. Topology wins.

D3 — Squid allowlist over deny-all+mirrors. Considered Verdaccio/devpi/apt-cacher mirrors (offline-first). Rejected as default: three caches to run and keep healthy, and agents legitimately need docs and APIs, not just packages. The allowlist proxy gives one policy file, full logging, and a 10-second change procedure (30-gateway.sh allow). Trade-off stated openly: an allowlisted domain is a standing grant — treat the file as production config.

D4 — Browsers baked once, seeded per-workspace. Two browser ecosystems must coexist (§3): Playwright's Chromium (per-version revisions) and agent-browser's own Chrome. Both are baked into /opt (image layers, ~2 GB unpacked, shared by every workspace) and symlinked into each workspace's writable home by an idempotent seeder. Projects pinning other Playwright versions download their revision through the proxy into their home volume — self-healing, no copy overhead for the common case.

D5 — --userns=keep-id:uid=1000,gid=1000. Rootless containers otherwise remap the host user to container-root, making bind-mounted project dirs unowned by the workspace user. keep-id:uid=1000 pins host user ↔ container dev (uid 1000) regardless of the host uid, so ~/agent-workspaces/<name> is transparently shared (IDE-editable on the host) and writable in-container. This also eliminates git's "dubious ownership" class of failures.

D6 — One image, two tiers (container-in-VM). The Tier-2 VM runs rootless Podman inside it and loads the same agent-dev-sandbox:1 image (transferred during the one-time golden build). Toolchain drift between tiers becomes impossible; only the enforcement point differs (VM nftables instead of network topology).

D7 — No sudo inside workspaces. A missing system package is an image bug: rebuild (minutes, cached). Granting sudo would re-open privilege escalation that cap-drop and no-new-privileges just closed. Language-level installs (npm/pip/uv) are unaffected.

D8 — Version-pinned ARGs, major-pinned repos. Every tool in the image is pinned to a version verified on 2026-11-05; Node comes from the NodeSource major repo; the base image can be digest-pinned for strict reproducibility (references/hardening.md §1). Refresh = bump ARG + rebuild + re-verify; never @latest in the image.

Alternatives considered and rejected: gVisor/Kata (not in Debian repos; adds a kernel-interposition layer with its own trust base — reasonable future option, documented in hardening §4); Firecracker/Cloud Hypervisor (excellent for fleets; QEMU+KVM is packaged, scriptable and sufficient for single-user hosts — boot_vm() is the only function that would change); full Docker-in-Docker (defeats isolation); remote dev containers (network dependency, opposite of self-contained).

Life of an egress request (the guarantee, step by step). A workspace process runs bun install. Bun reads https_proxy (injected as container env) and sends CONNECT registry.npmjs.org:443 to agent-gateway:3128 — the name resolves via aardvark-dns to the gateway's agent-internal interface, because that is the only resolver reachable. Squid matches the CONNECT target against the allowlist file (bind-mounted read-only from the skill bundle): allowed → Squid itself resolves DNS and proxies the TLS tunnel (payload never decrypted); denied → HTTP 403 plus one access-log line. If the process ignores proxy variables entirely and attempts a direct socket connection, the packet is dropped at the network layer: agent-internal has no default route and forwarding is disabled on the bridge. If it tries to smuggle a hostname past policy, there is no external DNS to resolve it with — aardvark answers container names only, everything else NXDOMAIN. Four independent mechanisms, one policy file.

Workspace model (per-project, persistent). A workspace = container + bind-mounted code dir + named home volume + env file. Stopping preserves everything; restart re-creates the container (re-reading the env file — key rotation without volume surgery); snapshot commits the container fs and tars the home volume; destroy removes the container, keeps code and home unless explicitly purged. Credentials for the agent CLIs live in the home volume, so logins survive container re-creation.

Tier-2 lifecycle. base (once): download + SHA512-verify the official cloud image → golden overlay → cloud-init (packages via the host proxy, the nftables ruleset, subuid ranges, linger) → transfer + podman load the agent image → freeze. create <name> (seconds): copy-on-write overlay of golden + boot + container start inside. Backing-file sharing makes overlays instant; the flip side — a poisoned golden poisons all overlays — is why hardening §4 recommends rebuilding golden per trust boundary.

6. Component specifications

Resource budget (16-32 GB host): gateway ~50 MB; each Tier-1 workspace default 6 GB/4 CPU cap (per-container) inside a user-slice budget; one Tier-2 VM 6 GB/4 vCPU by default. Comfortable: 2-4 active workspaces + 1 VM on 32 GB; 1-2 workspaces on 16 GB.

Secrets plumbing. Host file ~/.config/agent-sandbox/workspaces/<n>.env (0600, never committed, never in an image or snapshot) → --env-file at podman run. Agent CLI auth tokens live inside the home volume only. Tier-2 env files live inside the VM (~/.config/agent-sandbox/), so host compromise of the env dir does not automatically include VM workspaces' keys.

7. Representative workload fit — budget-wiser

The chosen reference repo stresses every axis of the design: Next.js 16 + React 19 need Node ≥ 24 (or Bun ≥ 1.3) — both provided; Prisma 6 + SQLite needs libssl/sqlite — provided; bun install needs registry.npmjs.org — allowlisted; db:push/db:seed are local file operations; Vitest runs offline; Playwright E2E launches Chromium against localhost — covered by no_proxy and the baked browser; agent-browser verifies UI state via accessibility snapshots. Onboarding inside a workspace:

scripts/40-workspace.sh create wiser --repo https://github.com/nordeim/budget-wiser.git
scripts/40-workspace.sh shell wiser
# in-workspace:
bun install && bun run db:push && bun run db:seed && bun run gate   # lint+type+unit
bun run dev &       # localhost:3000
agent-browser open http://localhost:3000 && agent-browser snapshot -i
bun run test:e2e    # Playwright, local server — no external egress needed

50-verify.sh performs the first step (clone via proxy) as a standing check; the rest is the documented user acceptance path.

8. Security analysis

Guarantees enforced by construction: workspace processes run as non-root with zero capabilities, no privilege escalation, and cgroup caps; the only route off the host user's network namespace is Squid with a domain allowlist (403 + logged for everything else); external DNS is unavailable; no host path is writable inside a workspace except the project dir (same host uid — worst case is "your own files in that dir", the same trust level as running the code by hand); Tier-2 adds a full VM boundary and keeps all host paths out entirely.

Verified, with caveats stated: rootless defined-network NAT egress is a standard podman 5 capability and the --internal semantics are documented; an exotic-host fallback (rootful system-quadlet gateway) is specified in references/troubleshooting.md §4. Chromium-family browsers do not reliably honor proxy env vars in every launch mode — external-page browsing via agent-browser is therefore a SOFT check with the explicit per-project Playwright proxy option documented; local dev-server testing (the dominant agent flow) is unaffected and hard-verified.

Known residual risks (by tier, see §2 table and hardening §6): shared kernel for Tier 1; supply chain of allowlisted domains; allowed-channel exfiltration; side channels on shared hardware. The design's answer to the first is the tier switch, to the second is allowlist governance + your normal package review, to the rest is stated scope.

9. Operational characteristics, logging & audit

Timing profile (mid-range host): image build 5-15 min (first) / seconds (cached); workspace create ~3 s + first seed-playwright-browsers (< 1 s); workspace restart ~2 s; gateway start ~1 s; Tier-2 golden build 15-30 min (one-time); Tier-2 overlay create ~40 s to SSH. A CI run adds ~5-8 s of overhead around the command itself (container create + browser seeding + isolation self-audit); artifact copying is size-dependent.

What happens on reboot: linger + the gateway Quadlet bring the proxy back automatically; stopped workspaces stay stopped (start them explicitly); running workspaces restart with their containers (Quadlet-less workspaces rely on podman start, a deliberate choice — agents should not auto-resume unfinished work unattended). VMs do not auto-start (their qemu processes are user-managed, not systemd units — keep it that way unless you add units yourself).

Audit trail: Squid access logs are the egress audit record — one line per proxied request and per denial. Container path: journalctl --user -u agent-gateway.service (or podman logs agent-gateway); Tier-2 host path: /var/log/squid/access.log. Answering "did workspace X contact domain Y?" is a one-line grep. Retention is your host's journald/logrotate policy — size the logs to your compliance needs.

Host maintenance: Debian security updates apply normally (host packages are outside all sandboxes). After a host kernel update + reboot, re-run 50-verify.sh before resuming untrusted work — the suite is cheap and the kernel is the Tier-1 boundary.

10. Design questions you will ask

Why not Claude Code's own sandbox / Codex's built-in sandboxing? Both CLIs ship process-level sandboxes (seccomp/Landlock/namespace wrappers). They harden the CLI's own tool calls — but the user may run other agents, ad-hoc commands, or a different CLI version; and process sandboxes do not provide resource caps, egress allowlists, or a reproducible environment. This blueprint treats agent-internal sandboxing as an optional extra layer inside the workspace, never as the boundary.

Why is the gateway a container instead of host squid for Tier 1? Rootless containers on an internal network cannot reach host loopback; the dual-homed gateway container keeps the entire Tier-1 plane inside the unprivileged user realm (no root-owned moving parts) and makes the whole thing portable via Quadlet. Tier 2 does use host squid — VMs reach it via QEMU's 10.0.2.2 mapping, which lands on loopback.

Why allow example.com but not a general docs allowlist? Every line is a standing grant to untrusted code. Two inert verification domains are shipped; anything else is a deliberate, reviewable policy decision via 30-gateway.sh allow. Agents that need docs access get it the same way — explicitly, observably, revocably.

Can a workspace use Docker/Compose inside? No — deliberately. Nested container runtimes need privileges this design refuses to grant. Projects needing multi-service topologies should use podman-in-VM (Tier 2, where rootless podman IS available inside the VM) or the host-side scripts.

12. Ephemeral CI profile

The roadmap's "ephemeral CI profiles" item, delivered. The insight that keeps it cheap: CI here is not a new environment but a new consumption mode of the one that already exists.

Mode Tool Lifecycle Home Code
Interactive workspace 40-workspace.sh persistent (stop/start/restart) named volume agent-home-<n> host bind ~/agent-workspaces/<n>
Ephemeral CI run 45-ci-run.sh one command, then destroyed container layer (or run-local bind with --read-only-rootfs) run dir, or --src checkout
Container-in-VM 60-tier2-microvm.sh per engagement inside the VM VM disk

Runner. 45-ci-run.sh run [--repo URL | --src DIR] [--timeout S] -- <command...> creates a single-shot container that is hardened exactly like a workspace — keep-id, cap-drop=ALL, no-new-privileges, agent-internal only, env-file secrets, pids/memory/cpu caps — plus a walltime timeout (default 3600 s). The command streams live and is captured to artifacts/console.log. Teardown always follows the run (--keep-on-failure opts out for debugging); reap removes orphans and stale run dirs past a TTL; list prints past runs from their summaries; cache wipes the shared package caches.

In-container preamble. files/ci-setup.sh is bind-mounted in (image unchanged — D6 holds): it sets CI=true (pnpm then defaults to a frozen lockfile in CI), points npm/pip/uv/bun/pnpm caches at the shared tree, seeds browsers, optionally shallow-clones CI_REPO_URL, then — before any workload code runs — audits isolation: uid 1000, zero caps, NoNewPrivs, direct egress must fail, external DNS must fail, the proxy must 403 a known-denied domain and 200 an allowlisted one. Results land in artifacts/isolation-audit.json; any failure exits 66 without running the command. Every CI run therefore carries its own evidence that the sandbox guarantees held for that run.

Artifacts. ~/agent-workspaces/__ci/artifacts/<run-id>/ keeps console.log, isolation-audit.json, a schema'd run-summary.json (exit code, duration, audit status, cache mode, copied files), and the report dirs the copier knows by default (playwright-report, test-results, coverage, dist, build, junit.xml; extend with --artifact-path, globs allowed).

Caches and trust. Shared caches are a host bind mount (~/agent-workspaces/__ci/cache → /cache) — deliberately not a named volume, because same-uid bind mounts are this design's proven primitive (D5); no orphan volumes can ever exist. The tree is shared writable state across runs: pnpm's own documentation makes exactly this point about its store, and the same reasoning applies to npm/pip/uv/bun caches. Same host, same user, same trust domain — fine for your own projects; --no-cache-vol gives a run cold, isolated caches when the source is less trusted, and hostile PR builds belong in Tier 2 (the same script runs inside the VM). CI mode changes consumption, never the trust tier.

Naming. Containers are agent-__ci-<run-id>, state lives under the __ci/ subtree of the workspaces root. 40-workspace.sh's validate_name reserves the __ prefix, so CI containers cannot collide with interactive workspaces and reap cannot touch them — the same structural reservation the verify canary (__verify) uses.

Representative run (budget-wiser gate):

scripts/45-ci-run.sh run --repo https://github.com/nordeim/budget-wiser.git \
    -- bash -lc 'bun install && bun run db:push && bun run db:seed && bun run gate'
scripts/45-ci-run.sh list

Exit codes are a contract: 0 ok · 66 audit failure · 124 walltime timeout · 125/126/127 podman-level error · anything else is the command's own exit code. See references/troubleshooting.md §9 for the failure playbook (including why --skip-audit is never a fix).

13. Verification as specification

50-verify.sh maps each guarantee to a check, and — crucially — encodes the negative tests as first-class requirements: direct egress must fail, external DNS must fail, non-allowlisted domains must 403. A green run is a reproducible evidence ledger (per-check PASS/FAIL with captured output), designed so an AI operator cannot honestly report "done" without it — and the escalation rule forbids weakening checks to force green. The CI profile extends the same idea to every single run: its self-audit is 50-verify's isolation section, in miniature, attached to each job's artifacts.

14. Roadmap

Registry mode (local podman push target for team-shared images); ephemeral CI profiles — delivered (§12); gVisor/Kata runtime option for Tier 1.5; DNS-level allowlisting in Tier 2 (dnsmasq allow-resolver); automated monthly golden rebuilds with drift reports. Each extension is a delta on this blueprint, not a redesign.
